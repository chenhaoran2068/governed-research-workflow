# v0.10.2 Human-Mediated Experience-Curation Maintenance Contract

Status: local pre-C3-remote maintenance-source contract. This record defines a narrow clarification of future experience-sharing direction. It does not itself prove a hosted tag, GitHub Release, installation target, installed runtime, C3 remote action, or C4 approval.

## Scope

This maintenance source adds no capability, schema, validator, dependency, receiving endpoint, automation, or external-contributor service. It clarifies only the following future direction:

1. A prospective contributor may prepare a minimal candidate only after clear consent.
2. Any future transmission must use a channel specified by a human, not an endpoint, helper, repository route, or automation provided by this package.
3. Chenhaoran must manually screen the candidate for rights and sensitivity, curate any derivative, and separately approve any public-safe publication.

## Non-Goals

This maintenance source does not add public or user-facing intake, upload or download tooling, repository access for contributors, authentication, credential handling, automatic de-identification, automatic screening, automatic promotion, telemetry, network transfer, real-content processing, multi-machine proof, correction execution, withdrawal execution, deletion, recall, or future-use-stop execution.

It does not modify the immutable `v0.10.1` tag or GitHub Release. It does not change the `v0.10` voluntary experience-package schema `1.0.0`, the `v0.10.1` synthetic exchange-pilot receipt schema, either validator, or their read-only behavior.

## Compatibility And Admission Boundary

`v0.10.2` is a zero-new-capability maintenance source. No `GRW-CAP-*` item is re-admitted, migrated, or newly admitted for this version. The existing release-control JSON schema requires one or more capability identifiers for an exact capability-release scope; it is therefore intentionally not used to invent a zero-capability admission for this maintenance source.

The retained `v0.10.0` and `v0.10.1` records keep their historical capability and pilot boundaries. A normal public installation target for a selected `v0.10.2` version exists only when the version-neutral exact-tag and matching-GitHub-Release rule in `CURRENT_RELEASE_STATUS.md` is independently verified.

## Required Release Review

Before any later C4 decision, review the exact candidate diff, this contract, the public-material and rights review, dependency and workflow review, release evidence, release notes, full local tests, exact-candidate three-platform CI, protected-main result, and the exact proposed tag and hosted Release action. If any source text implies a contributor intake service, a direct upload route, or automatic curation, stop the release and revise the source under a new review cycle.
