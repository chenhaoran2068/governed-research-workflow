# v0.12.0 Release Notes

Status: versioned release-source notes. This file describes bounded source
scope only and does not by itself prove an annotated tag, matching GitHub
Release, installation target, or runtime update.

## Added

- One synthetic integration-assurance scenario that composes existing bounded
  bootstrap, provenance, workflow/evidence, lesson-promotion, and blank
  manuscript-governance surfaces.
- Regression coverage for a test-owned temporary staging/update/rollback
  simulation, binary-stable tracked snapshots, ignored untracked support
  directories, and the rule that an invalid record is not an approval.
- Versioned release-preparation records that preserve the no-new-interface
  scope, material boundary, workflow/dependency review, gate, and evidence.

## Boundaries

- v0.12 adds no capability identifier, schema, validator, helper, dependency,
  profile, role, agent runtime, delegated authority, network route, external
  service action, data route, generic installer, or real rollback executor.
- The assurance path uses only blank, synthetic, fixture, or temporary
  test-owned content. It does not access real data, manuscripts, project
  material, credentials, external services, or private source/runtime paths.
- A successful synthetic integration result does not prove that a real
  installation or rollback worked, a person is authorized, a record is true,
  data are accessible, a requirement is current, or a research, compliance,
  Gate, publication, or submission decision is approved.

## Compatibility

Existing capability contracts, schemas, validators, helper interfaces,
dependencies, supported profiles, framework identity, and CI architecture are
unchanged. Public Release, private canonical source adoption, and Codex
runtime installation remain separate controlled decisions.
