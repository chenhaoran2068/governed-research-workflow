# v0.12 Synthetic Integration Assurance Scope

Status: local pre-C3-remote assurance-scope record. It describes a source
candidate only. It is not a hosted Release, installed runtime, real update,
real rollback, or C4 authorization.

## Exact Scope

v0.12 adds no capability interface and creates no `GRW-CAP-120-*` record. It
adds one synthetic integration-assurance scenario and test coverage which
composes existing bounded controls without changing their interfaces:

1. preview and matching confirmation for the existing empty-workspace
   bootstrap, inside a temporary test-owned directory;
2. structural review of existing synthetic provenance-register-set,
   workflow/evidence-control, and lesson-promotion fixtures;
3. review that existing manuscript-governance templates remain blank and
   accountable-human governed; and
4. a temporary, test-owned source-copy staging, activation, and rollback
   simulation using only declared Git-tracked files.

The assurance scenario rechecks existing `GRW-CAP-031-02`, `GRW-CAP-050-01`,
`GRW-CAP-060-01`, `GRW-CAP-070-01`, and `GRW-CAP-110-01` through
`GRW-CAP-110-05`. It does not re-admit them, change their release contracts,
or make an installation claim.

## Required Boundaries

- Only blank, synthetic, fixture, or temporary test-owned content is used.
- The source snapshot uses declared tracked paths, preserves binary bytes, and
  ignores untracked cache, staging, and CI-support directories.
- Existing bootstrap path/reparse-point controls remain the only applicable
  protection for a real workspace path. This scenario does not create a new
  path or reparse-point helper.
- A structurally valid record does not establish data access, rights, ethics,
  compliance, a Gate decision, scientific truth, publication readiness, or
  submission authority.
- The temporary lifecycle simulation does not modify a private canonical
  source, an installed Codex runtime, a receipt, a real backup, or a project.

## Explicit Non-Goals

v0.12 does not add a schema, validator, helper, dependency, profile, role,
agent runtime, delegated authority, network or external-service action,
real-data or manuscript handling, generic update installer, real rollback
executor, release action, or runtime-installation behavior.

## Required Later Evidence

Before any public Release can be considered, an exact candidate must receive
refreshed local regression, static public-boundary review, separately
authorized Windows, Ubuntu, and macOS CI, protected-main review, an exact C4
decision, and post-release tag/Release verification. Those steps remain
separate from this source-scope record.
