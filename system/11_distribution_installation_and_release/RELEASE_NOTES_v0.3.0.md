# Release Notes: v0.3.0

Status: release-note source. The GitHub Release records the exact final main
commit, validation links, human authorization, and post-release verification.

## Bounded System Foundation

v0.3.0 promotes Governed Research Workflow from a thin workflow package with
supporting resources to a bounded public system foundation. It retains the
thin, human-governed Codex entry and makes its module ownership, profiles, and
future extension boundaries explicit.

This is a pre-1.0 release. It does not claim a complete research platform or
universal agent compatibility.

## Included

- a root SYSTEM_MANIFEST.yaml with standalone and framework_integrated
  profiles;
- a 13-module public system map with active and foundation-only distinctions;
- validated synthetic framework integration against the exact released
  governed-research-workspace-framework v0.1.0 tag;
- existing controlled empty-workspace bootstrap, blank records, route
  references, and regression checks; and
- manual installation, update, rollback, public-material review, and release
  integrity documentation.

## Compatibility

- Codex-first skill interface; no claim of compatibility with every agent.
- Python 3.11 or later for the optional bootstrap helper and test commands.
- Standalone profile with bundled public resources only.
- Optional framework_integrated profile only with Workspace Framework v0.1.0.
- No automatic system installer, updater, migration utility, or project
  creation authority.

## Deferred Or Excluded Capability

The following remain explicitly outside the v0.3.0 release claim:

- clinical, restricted, patient-derived, or external-data processing;
- a runnable specialist-agent suite or autonomous research execution;
- clinical, scientific, ethical, legal, compliance, or journal certification;
- final scientific conclusions, submission authority, or autonomous release;
- a bundled knowledge corpus, journal-rule corpus, source PDFs, or real
  project example; and
- technical GitHub immutable releases. The v0.3.0 compensating controls are
  documented in RELEASE_INTEGRITY_POLICY_v1.md.

## Validation

Before publication, the release maintainer must replace this section with the
exact final main commit identifier and links to:

- successful GitHub Actions matrix runs on Windows, Ubuntu, and macOS with
  Python 3.11 and 3.14;
- the local regression command result;
- the exact released Workspace Framework v0.1.0 integration evidence; and
- the completed R30-G1 through R30-G6 evidence record.

The tests establish only the documented technical behavior. They do not prove
scientific quality, compliance, data access, real-project safety, or every
agent/runtime compatibility.

## Upgrade And Rollback

Existing v0.2.1 users do not need a project migration. v0.3.0 adds public
system-foundation contracts and documentation while preserving the thin
routing and explicit bootstrap boundaries.

Use the exact-tag update and rollback procedure in INSTALL_UPDATE_ROLLBACK.md.
Do not overwrite a locally modified package, use a branch name as a release
identity, or store project material in the package checkout.

## Release Integrity

This release must use an annotated v0.3.0 tag at the exact approved main
commit. The GitHub Release and generated source archives must refer to that
tag. Corrections use a new version rather than a silent rewrite.
