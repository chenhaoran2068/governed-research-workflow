# Substantive Content Before Supporting-Material Reference

## Purpose

When a response, report, review, or manuscript refers to a table, figure,
attachment, file, link, log, code artifact, report, or other supporting
material, the reference must not replace the substantive delivery owed to the
reader.

State the task-relevant finding, change, conclusion, or impact first. Then
provide the reference so the reader can verify or inspect detail.

## Proportionate Delivery

| Material role | Reader-facing content before the reference |
| --- | --- |
| Primary result, decision, or consequential change | State the key finding or change, its direction or disposition, material degree, and necessary basis or limitation. |
| Secondary result or supporting analysis | State the core result and whether it changes the primary conclusion. |
| Large attachment or log | State the portion relevant to the present task and why it matters. |
| Explicit navigation-only request | A location-only answer is permitted when the requester asks only for an index, directory, or link list. |

## Review Question

Before closing a reader-facing communication, ask: can a reader who does not
open the supporting material still understand what happened, the principal
result or impact, and why the material was cited? If not, complete the
substantive delivery before relying on the reference.

## Boundaries

This guidance governs communication form, not scientific truth, source
adequacy, result authority, current external requirements, approval, access,
release, or submission. It does not require disclosure of restricted material.
Stop and seek an accountable-human decision when giving enough context would
expose restricted, confidential, or otherwise non-shareable material.
